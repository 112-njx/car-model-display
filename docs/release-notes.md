## 兼容性

| 端 | 要求 | 说明 |
| --- | --- | --- |
| 桌面 | Chrome / Edge（近两年版本） | 渲染后端**固定为 WebGL**（人工裁定：WebGPU 路径存在 three 后端的未捕获异常，会打死帧循环，详见 `docs/debug.md` 记录 T8-03） |
| 手机 | Chrome（Android）；Safari 不支持语音 | 语音需 **https 或 localhost**；局域网 `http://<IP>` 下麦克风会被拒绝，应用内已给中文降级提示 |
| 其他 | Firefox / Safari | 3D 与交互可用，语音入口显示"请用 Chrome 或 Edge" |

## 已知限制

1. **手机语音需 https**：局域网 http 调试时语音不可用（属浏览器安全策略，非缺陷）。
2. **弱机自动降档**：帧率持续偏低时自动降到低画质档，该档会**关闭反射地面**（视觉观感下降，换取流畅度）。
3. **性能目标待真机复核**：桌面 ≥55fps / 手机 ≥30fps 的达标结论需在正常桌面机与真机上复核（本机为 Intel UHD 核显且多任务并行，测不准）。
4. **`file://` 双击打开 dist 不可用**：Chrome 对 `file://` 源以 CORS 拒绝加载 ES module 与 CSS（浏览器安全策略）。
   交付形态为"**任意静态服务器托管**"（含子路径），已在 `http://<host>/<任意子路径>/` 下实测通过。

## 部署章节

- **托管平台**：GitHub Pages（`.github/workflows/deploy-pages.yml`，手动触发）。
- **公网 URL**：⟨首次部署完成后回填：`https://112-njx.github.io/car-model-display/`⟩
- **https**：由 GitHub Pages 自动提供，是手机语音控车（Web Speech API）的硬性前提。
- **真机复验**：部署完成后需在桌面与手机 Chrome 复验四项核心功能（拖动旋转 / 点击控车 / 语音控车 / 车灯效果），结论回填此处。

### 部署方式（T10a 已备好配置）

| 方式 | 配置文件 | 命令 / 步骤 |
| --- | --- | --- |
| 本地静态服务器 | — | `cd app && npm run build && npm run preview` |
| 任意静态托管（含子路径） | `app/vite.config.js` 的 `base: './'` | 把 `app/dist/` 整个目录传上去即可，无需改配置 |
| Vercel | `vercel.json` | 关联仓库后自动按配置构建部署 |
| GitHub Pages | `.github/workflows/deploy-pages.yml` | 先在 Settings → Pages 把 Source 设为 "GitHub Actions"，再手动触发该 workflow |

> `base: './'` 使产物可在**任意子路径**下工作（Pages 的 `/<repo>/`、内网静态服务器的任意目录），
> 且资源引用全部为相对路径。已在 `http://127.0.0.1:4321/app/dist/`（子路径）实测：10 部件、12 命中目标、
> 字节级加载进度（80.6% → 100%，22671680 字节）全部正常，控制台 0 异常。
