# 双端验收清单（qa-checklist.md）

> 项目：3D 仿真车模 Demo　|　规划依据：`docs/roadmap.md` §11.1 T9、§12.3 Wave 2
> 归属：T9（验证 Agent）独占　|　用途：**Wave 2 验收执行段**的人工验收依据
> 配套自动化脚本：`scripts/verify-{parts,pick,voice,camera}.mjs`（T9 独占，见 §2）
> 产出：按 §4 的格式执行后填成 `docs/qa-report.md`

**口径**：本清单分「自动化可覆盖」与「只能人工确认」两类。自动化能覆盖的**必须**先由脚本跑绿
（§2），人工只确认脚本覆盖不到的部分：视觉观感、真机触摸手感、真机语音、性能体感、跨端布局。

## 1. 环境准备

### 1.1 起被测页面（二选一）

| 形态 | 命令（在 `app/` 下执行） | 地址 | 说明 |
| --- | --- | --- | --- |
| dev（推荐验收用） | `npm run dev -- --port 5173 --strictPort` | `http://127.0.0.1:5173/` | **必须带 `--strictPort`**：本机 5173 常被其他 Vite 实例占用，端口被顶掉后会自动落到 5174，而那个实例上没有你的改动 —— 会得到**假绿**（现象与根因见 `docs/debug.md` T2 记录 06） |
| dist（交付形态） | `npm run build && npm run preview -- --port 4173 --strictPort` | `http://127.0.0.1:4173/` | 验「产物形态」时用；`base:'./'` 生效后 dist 也可直接双击打开 |

### 1.2 起一个带调试端口的浏览器（自动化脚本的前提）

脚本**不启动浏览器**，只连接一个已开调试端口的 Chrome/Edge。桌面/无头均可，无需关掉你正在用的窗口：

```bash
# Edge（本机已装：C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe）
"C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" \
  --headless=new --remote-debugging-port=9222 \
  --user-data-dir=%TEMP%\car-display-edge --no-first-run --no-default-browser-check \
  --window-size=1440,900 about:blank
```

脚本会依次探测 `9222 / 9333 / 12319`，也可用 `--debug-port=<端口>` 指定。

> **⚠️ 需要人工配置**：本项目 Wave 1 的 Agent 会话被 worktree 隔离守卫限制，**无法自行启动工作目录之外的
> 可执行文件**，因此上面这条命令必须由项目负责人执行（在会话里用 `!` 前缀粘贴，或在
> `~/.config/safe-chains.toml` 放行 msedge.exe 路径）。详见 `docs/debug.md` 人工配置区。

### 1.3 手机真机

| 项 | 要求 |
| --- | --- |
| 网络 | 手机与开发机同一 Wi-Fi（校园网可能开启 AP 客户端隔离，届时改用手机热点） |
| 地址 | 开发机 WLAN 地址见 `docs/debug.md` 人工配置区；dev 形态为 `http://<开发机IP>:5173/` |
| 浏览器 | **Chrome（Android）/ Safari 不支持语音**，语音项仅 Chrome 可验 |
| **语音项硬性前提** | Web Speech API 要求**安全上下文**：`https://` 或 `localhost`。**局域网 `http://<IP>` 下手机 Chrome 会拒绝麦克风** —— 语音项须等 T10b 的 https 在线 URL（`docs/release-notes.md`）到位后再验；在此之前该项一律标「阻塞（待 https）」，不得标「通过」 |

## 2. 自动化脚本（先跑脚本，再人工）

四个脚本**只依赖** `docs/roadmap.md` §13.3 冻结的钩子/注入点，不 import 工程实现。未集成项一律
打印 `[SKIP]` 并说明原因（不假绿）；`--strict` 时 SKIP 计入失败（Wave 2 验收用）。

| 脚本 | 覆盖 | 关键用例 |
| --- | --- | --- |
| `node scripts/verify-parts.mjs` | 10 部件 + 2 灯光 | 逐一驱动 → `__carDisplaySceneAudit()` 终态与动画进度；分组开关；`closeAll`；未知 id 拒绝 |
| `node scripts/verify-pick.mjs` | 3D 点击拾取 | `hitTargets[].screen` 派发真实鼠标/触摸事件 → 开合翻转；**拖拽位移不触发点击**；长按不触发；命中即 toast |
| `node scripts/verify-voice.mjs` | 语音链路 | 注入 `scripts/mocks/speech-recognition-mock.js` 回放 §6 全部指令集（18 条）→ store 动作 + toast；错误路径；传 `null` 恢复 |
| `node scripts/verify-camera.mjs` | 相机 | 4 个预设 view；`orbit-once` 环绕一周回正；待机自转与交互即停；拖拽旋转 |

常用参数：

```bash
node scripts/verify-parts.mjs  --base-url=http://127.0.0.1:5173/ --debug-port=9222
node scripts/verify-pick.mjs   --mobile                 # 375×812 手机视口
node scripts/verify-camera.mjs --fast                   # 跳过需等 8s 的待机自转用例
node scripts/verify-voice.mjs  --report=docs/qa-artifacts/verify-voice.json --strict
```

| 参数 | 作用 |
| --- | --- |
| `--base-url=<url>` | 被测地址，默认 `http://127.0.0.1:5173/`（亦可用环境变量 `CAR_DISPLAY_BASE_URL`） |
| `--debug-port=<port>` | CDP 调试端口，默认自动探测 9222/9333/12319 |
| `--width/--height/--mobile` | 视口，默认 1440×900 |
| `--strict` | SKIP 计入失败（**Wave 2 验收必须带**） |
| `--fast` | 跳过慢用例 |
| `--report=<path>` | 输出 JSON 报告（可直接作为 `qa-report.md` 的证据附件） |
| `--keep-open` | 保留标签页便于肉眼查看（调试用） |

**脚本判读**：退出码 `0` = 全绿；`1` = 有 FAIL（或 `--strict` 下有 SKIP）。每个 FAIL 都带
「期望 / 实得」，可直接作为 issue 描述回流 T8。

## 5. 与自动化脚本的分工（避免重复劳动）

| 能力 | 自动化脚本 | 人工 |
| --- | --- | --- |
| 部件开合终态 / 动画进度 | ✅ verify-parts | 只确认「看起来自然」 |
| 点击命中 / 拖拽不误触发 | ✅ verify-pick（真实指针事件） | 只确认手感与命中率体感 |
| 语音指令 → store + toast | ✅ verify-voice（mock 回放，确定性） | **真机语音识别准确率**（含口音、噪声）—— 只能人工 |
| 相机预设 / 环绕 / 待机自转 | ✅ verify-camera | 只确认观感（是否突兀） |
| 视觉风格、文案、布局、性能体感、跨端 | ❌ 脚本覆盖不到 | 全部人工 |
